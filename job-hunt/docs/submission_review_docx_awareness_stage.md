# Submission Review DOCX Awareness Stage

This stage does not change the frozen pipeline. It strengthens the existing `submission-review-gate` so it understands DOCX resume/CV export artifacts generated by `resume-tailor`.

## Current project consolidation

The project is now in the **multi-job regression and document artifact integration stage**.

The main pipeline is stable enough to:

1. normalize jobs,
2. score fit,
3. tailor resume positioning,
4. generate Japanese application drafts,
5. generate Markdown resume/CV artifacts,
6. export DOCX resume/CV artifacts,
7. track application artifacts,
8. produce pre-submission review packages,
9. generate controlled live dry-run packages.

## Frozen pipeline

```text
job-normalizer
→ job-fit-scorer
→ resume-tailor
→ jp-application-writer
→ application-tracker
→ browser-apply-assistant
→ submission-review-gate
→ live-submission-adapter
```

There is no `submission-session-orchestrator`.

## Why this stage exists

After DOCX export and tracker DOCX linkage, `submission-review-gate` should be able to review the actual `.docx` files that may be used for application upload.

It should distinguish between:

- Markdown resume/CV artifacts,
- DOCX resume/CV artifacts,
- missing files,
- present files that still require human layout review.

## Required behavior

When this file exists:

```text
outputs/resumes/<job_basename>_docx_export_manifest.json
```

`submission-review-gate` must record these fields in:

```text
outputs/logs/<job_basename>_submission_decision.json
```

Required fields:

```json
{
  "resume_docx_file": "",
  "cv_docx_file": "",
  "docx_export_manifest": "",
  "docx_human_layout_review_required": true
}
```

The review Markdown must include:

```md
## DOCX Export Artifacts
```
